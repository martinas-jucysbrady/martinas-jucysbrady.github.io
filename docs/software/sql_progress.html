1. Database Design & ERDs

Before writing a single line of SQL, a well-designed database starts with an Entity-Relationship Diagram (ERD). An ERD maps out the entities, their attributes, and the relationships between them.

Conceptual ERD — Car Insurance Database

A key exercise from the module involved designing a database for a car insurance company with the following requirements:

  • Each driver has a licence number, full name, and address — and can be insured for more than one car
  • Each car has a registration number, model and year — with only one driver insured per car
  • Each accident has a report number, cost, location and date — associated with only one car

The relationships expressed in min-max notation:

Entity A Relationship Entity B Cardinality
Driver insures Car (1,1) to (1,N)
Car involved in Accident (0,N) to (1,1)

A driver must insure at least one car but can insure many. A car is insured by exactly one driver. An accident is associated with exactly one car, and a car may have had zero or many accidents.

2. Creating Tables

Once the ERD is designed, the physical implementation in SQL uses CREATE TABLE statements with appropriate data types, primary keys and foreign keys.

Show code 
conn = sqlite3.connect(':memory:')
cur  = conn.cursor()

cur.executescript("""
-- Car insurance database
CREATE TABLE Driver (
    licence_number VARCHAR(20)  PRIMARY KEY,
    full_name      VARCHAR(100) NOT NULL,
    address        VARCHAR(200)
);

CREATE TABLE Car (
    reg_number     VARCHAR(20)  PRIMARY KEY,
    model          VARCHAR(50)  NOT NULL,
    year           INTEGER      NOT NULL,
    licence_number VARCHAR(20)  NOT NULL,
    FOREIGN KEY (licence_number) REFERENCES Driver(licence_number)
);

CREATE TABLE Accident (
    report_number  INTEGER      PRIMARY KEY AUTOINCREMENT,
    cost           DECIMAL(10,2),
    location       VARCHAR(200),
    accident_date  DATE,
    reg_number     VARCHAR(20)  NOT NULL,
    FOREIGN KEY (reg_number) REFERENCES Car(reg_number)
);
""")
print("Tables created successfully.")

6. Joins & Aggregations

Joins combine data from multiple tables. Aggregations summarise it. Together they answer the most important analytical questions.

TipJOIN types
  • INNER JOIN — only rows with matches in both tables
  • LEFT JOIN — all rows from the left table, NULLs where no match on the right
  • RIGHT JOIN — all rows from the right table (not supported in SQLite, use LEFT JOIN reversed)
  • FULL OUTER JOIN — all rows from both tables
Show code 
# Customers who ordered more than one type of book
print("Customers with more than one type of book ordered:")
df_multi = pd.read_sql("""
    SELECT c.name, COUNT(DISTINCT o.book_id) AS book_types
    FROM Customer c
    INNER JOIN Orders o ON c.customer_id = o.customer_id
    GROUP BY c.customer_id, c.name
    HAVING COUNT(DISTINCT o.book_id) > 1
""", conn)
print(df_multi.to_string(index=False))

# Total spend per customer (Price × Quantity)
print("\nTotal spend per customer:")
df_spend = pd.read_sql("""
    SELECT c.name,
           ROUND(SUM(b.price * o.quantity), 2) AS Total_Spent
    FROM Customer c
    INNER JOIN Orders o ON c.customer_id = o.customer_id
    INNER JOIN Book   b ON o.book_id     = b.book_id
    GROUP BY c.customer_id, c.name
    ORDER BY Total_Spent DESC
""", conn)
print(df_spend.to_string(index=False))

7. Subqueries

Subqueries allow you to nest one query inside another — useful for filtering based on aggregated results.

Show code 
# Books priced above the average price
print("Books priced above average:")
df_above = pd.read_sql("""
    SELECT title, price
    FROM Book
    WHERE price > (SELECT AVG(price) FROM Book)
    ORDER BY price DESC
""", conn)
print(df_above.to_string(index=False))

# Customers who have placed at least one order
print("\nCustomers with at least one order:")
df_ordered = pd.read_sql("""
    SELECT name, city
    FROM Customer
    WHERE customer_id IN (SELECT DISTINCT customer_id FROM Orders)
""", conn)
print(df_ordered.to_string(index=False))

    total_revenue DECIMAL(12,2),

# Insert representative data matching the real dataset structure
regions  = ['Europe','North America','South America','Asia','Africa']
products = ['Laptop','Smartphone','Solar Panel','Building Material','Car','Insurance Plan']
np.random.seed(42)
for r in regions:
    for p in products:
        for y in range(2021, 2025):
            profit  = round(float(np.random.uniform(-200000, 400000)), 2)
            revenue = round(float(np.random.uniform(500000, 2000000)), 2)
            ucost   = round(float(np.random.uniform(200, 600)), 2)
            cur.execute(
                "INSERT INTO EcoEnergy VALUES (?,?,?,?,?,?)",
                (r, p, y, profit, revenue, ucost)
            )
conn.commit()

# Net profit by region
print("Net profit by region (2021-2024):")
df_eco = pd.read_sql("""
    SELECT region,
           ROUND(SUM(net_profit)/1000000.0, 2) AS net_profit_M
    FROM EcoEnergy
    GROUP BY region
    ORDER BY net_profit_M DESC
""", conn)
print(df_eco.to_string(index=False))

# Median unit cost by product

df_cost = pd.read_sql("""
