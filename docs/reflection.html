Reflection

What I built, what I learned, and what’s next

A reflection on building this ePortfolio

This page is a quick look back at the portfolio itself (what went into building it, what I figured out along the way, and what I want to do once I’ve graduated).

1. What I Built

The whole site is built with Quarto, version-controlled with Git, and published on GitHub Pages. Four years of academic work, project pages, travel experiences, and software skills are all in one place.

The analytics project pages have live executable Python code, which means the charts on those pages aren’t screenshots and they regenerate every time the site builds. If I ever fix a bug in an analysis or update a dataset, the page updates with it.

2. What I Picked Up

Building the site needed a wider mix of skills than any single module had asked for. Four areas in particular:

Git

I’ve now used Git to clone, add, commit, push and repeat. Building this over months forced me to use it properly. Writing commit messages that actually describe what changed and going back through history to find when something broke, which happened more often than I wanted

NoteWhat Git is actually for

Git isn’t really about backup. It’s about being able to look back at what changed and why. A commit message like fix TOC overlap on ml_python page is far more useful three weeks later than update.

Quarto

This was completely new territory for me too. The configuration in _quarto.yml, writing in .qmd files, YAML front matter, embedding Python chunks, deploying to GitHub Pages are all something I haven’t touched before this project.

The thing that took me longest to appreciate is that Quarto isn’t just for documents. It’s a system for tying writing, code, and publishing together so that each piece stays in sync with the others. That’s why every chart on this site is live code rather than an image, the moment I update the underlying analysis, the chart updates with it. Once I got used to that, going back to static screenshots in a Word doc started to feel a bit primitive.

Python

The project pages let me use Python beyond individual assignments; across multiple datasets, with consistent visual styling, and with code that someone else could actually read. The brain tumour project in particular pushed me to think about methodology rather than just getting an answer out.

SCSS and a bit of design

I’d never written SCSS before this. Sass variables, custom rules, responsive layouts and hover animations were all new. The site’s colour palette, the fonts, the way the grid cards animate when you hover them, the way the navbar looks: none of that came out of the Quarto theme by default. It got built piece by piece.

What I didn’t expect was how much front-end design changes the perceived quality of the work. Two pages with the same content but different layouts read very differently; one looks effortful, the other looks rushed. I used the SCSS to design lots of very small details throughout.

3. The Hardest Part

The hardest part wasn’t learning any one tool. It was the slow, frustrating loop of trying something, having it not work, figuring out why and then trying again.

Almost nothing worked first time. A layout that looked fine in preview broke once it deployed. A Python chunk that ran locally failed when GitHub built the site. A YAML setting I was sure should override the global config didn’t, so I had to use the SCSS. Each one was its own small puzzle, and none of them had a clean Stack Overflow answer.

What I got out of it is that the actual skill is being systematic about testing. Change one thing at a time. Understand why it works, not just that it does. When something keeps breaking, go back to basics instead of stacking more workarounds on top.

TipThe most useful habit I picked up

Keeping quarto preview running in one window while editing in another. The feedback loop is fast enough most of the time so that you can try something, see it fail, and fix it within a minute. That’s the right pace for learning a new tool.

4. What I’m Proud Of

What I’m most proud of isn’t any single page; it’s that I kept improving the site for months after I could have stopped. But, the map is probably one of the cooler aspects of the website and was very interesting to build.

The earliest version of this site looks nothing like what’s here now. Not because of any one big change but because of months of small ones.

6. What’s Next

The plan after graduating is a Master’s degree. I want another year to go deeper on the parts of the degree I’m most drawn to and to get a clearer read on where I’m strongest before moving into industry. The mix of business and data skills my degree gave me is a solid base but there’s just more I want to know.

In terms of direction, I’m most drawn to data analyst roles, where I would turn complex data into something a business can actually act on. The projects on this site reflect that: EcoEnergy’s profitability analysis, the portfolio project, the brain tumour research paper. They’re all variations on the same theme; getting an answer out of data, then making the answer make sense to someone else.

Longer-term, I’d like to work somewhere the international perspective I’ve built up; studying in Japan, working with global datasets, comparing markets across regions, is doing real work, not just sitting on a CV.

NoteWhat I want to learn next
  • Deeper machine learning - moving past classical methods to neural networks once I’ve got a dataset that can actually justify them
  • Cloud platforms - AWS or similar systems, to understand what scaling actually looks like
  • Advanced SQL and Excel - window functions, stored procedures, query optimisation

7. One Last Thing

This was the most complete project I worked on at university. Not the most technically difficult, but the one that asked the most of me over the longest stretch of time.

The tools were all learnable. The harder bit was knowing what good looked like and being honest enough to keep going until the work hit that bar. That’s the habit that I want to bring with me into a Master’s, into whatever job comes after, and into anything else worth doing properly.

The site is at martinas-jucysbrady.github.io. It’ll keep changing.
